一个面向青岛大学学生的 Android 校园服务客户端。它把散落在学校各个网站与小程序里的日常事务收进一个应用：查课表、看校内通知、查宿舍电费、预约自习座位、检索图书馆藏书、报修宿舍设施、扫机身码使用水电设备，装一个 App 就都够用了。

> 本项目**不是青岛大学官方应用**，由个人开发维护，任何人可自行下载安装使用。学校官方系统随时可能改版，某个功能失效不代表 App 坏了，维护者会尽快跟进修复。

## 它解决什么问题

青大的各类服务分散在十几个网站与小程序里，每个都有自己的登录入口，在手机浏览器里使用体验也很差。这个 App 做的事情很直接：

- **一次登录，处处可用**。登录一次学校统一认证，之后打开办事大厅、预约座位、宿舍报修、图书馆检索等系统都不用再输账号密码。App 只负责携带会话，全程接触不到你的密码。
- **手机上好用**。课表、通知、座位预约、宿舍电费等高频功能做成了原生界面，不再依赖手机上挤成一团的网页。
- **没网也能看**。课表和通知都有本地缓存，断网时显示上次的数据，并如实标注数据更新于什么时候。

## 设计理念

这个 App 是工具，做它只有一个目的：把你该办的事快点办完，然后让你去忙别的。

- **为你省时间，不指望你多停留**。查询课表、看一眼电费余额这类事，打开 App 几秒内就能得到答案；查完就该走，App 不会用信息流、推荐或者红点把你留下来。你花在它身上的时间越短，说明它做得越合格。
- **隐私是前提，顺便也是省心**。数据全在本机、密码不经过 App、没有任何统计与上报（详见下文「隐私与数据安全」），你不需要先研究它的条款才敢用。
- **界面直白**。每页只回答一个明确的问题：课表页答「这周有什么课」，通知页答「最近发了什么通知」。文字写的是人话，该给的数据如实给，缺了或取不到就直接说，不用装饰性的动效和模棱两可的占位文案撑场面。

## 功能一览

### 研究生

- **课表**：读取研究生系统课表，按周展示，支持单双周与非连续周次、跳周、当前节次高亮、课程详情。学期与每节课的起止时间都可以在 App 内调整。
- **校内通知**：合并研究生院（培养、学籍、学位）与教务处教务通知两个来源，按时间倒序展示，可按关键词筛选，命中关键词的新通知会发本地提醒。
- **宿舍电费**：绑定宿舍编号后可随时查看空调电费余额与剩余电量；充值本身跳转学校网页完成，App 不经手任何支付。

### 本科生

- **课表**：选择自己的行政班即可查看课表。数据来自教务处信息公开的课程总表，随 App 一起发布，不需要登录（一学期更新一次，随新版本 App 发布）。页面上会固定提示：如需准确个人课表，请登录本科教务系统。
- **教务通知**：教务处的教务通知列表。

### 通用

- **扫码**：首页顶部的通栏扫码卡直达扫码页，扫饮水机、洗衣机、空调等设备机身上的码。App 在手机本地识别并判断码的归属，自动转交给对应的应用：微信码交给微信，支付宝码交给支付宝，学习通码交给学习通，其余网页类结果由你在系统选择器里自选应用打开。都打不开时可以复制链接，或直接从结果面板打开微信、支付宝，用它们自带的扫一扫重扫这个码。识别模型内置在安装包里，纯离线工作，不依赖任何云服务。
- **预约座位**：查看自习室座位平面图、预约与取消、提前离开，操作与网页端规则一致。
- **宿舍报修**：查看我的报修单与进度，可以直接在 App 里新建报修（含拍照上传）。
- **图书馆**：检索馆藏、查看每本书的在架状态与存放位置、查看自己的借阅与到期情况。
- **办事大厅**：按分类浏览学校服务清单，可搜索，带待办计数。
- **学工评奖评优**：查看奖助申请的批次信息与自己的申请记录（只读）。
- **校园网**：识别是否连接校园网（QDU-1X 与 QDU-Web 都算），显示本机 IPv4 与 IPv6 地址，提供网页认证入口；认证本身交给系统完成，App 不代填账号密码。
- **统一认证登录**：首次使用时在内置页面完成一次学校统一认证，学号自动预填，密码只在学校的登录页输入。

## 隐私与数据安全

这一点是这个项目最在意的部分：

- **无服务端**。App 直接与学校系统通信，开发者不运行任何服务器，也就不掌握任何用户数据。
- **数据全部留在本机**。课表、通知、凭据、缓存都只存在你的手机上，卸载 App 即全部清除。
- **不保存密码**。App 从头到尾不读取、不存储任何密码；密码只由学校官方登录页接收。凭据（登录 Cookie 等）使用 Android 系统的加密存储保存。
- **无统计、无上报**。不接入任何统计 SDK，不做崩溃上报；崩溃日志只写在本机文件里，是否导出、发给谁都由你自己决定。

## 下载与安装

本项目不上架应用商店，通过安装包（APK）分发。系统要求 **Android 13（API 33）及以上**。

1. 从项目的 Release 页面下载最新的 APK 文件。如果 Release 页没有可用包，也可以按下一节自行构建。
2. 在手机上打开下载好的 APK。系统会提示「来自未知来源」，确认允许安装即可（不同品牌的手机入口略有差异，一般位于安装时的弹窗或系统设置的安装权限里）。
3. 打开 App，按引导登录学校统一认证后即可使用。

### 更新

App 内「更多 · 关于 · 检查更新」会自动查询 GitHub Releases 并与本机版本比较：有新版本时弹窗显示更新说明并提供 Release 页入口；没有或暂时查不到就提示当前已是最新。你也可以随时到 Release 页手动下载 APK 覆盖安装，覆盖安装不会丢失课表缓存与登录状态。

### 自行构建

如果你想自己从源码构建，需要 Android Studio（或 JDK 17+ 的命令行环境）：

```bash
./gradlew :app:assembleRelease
```

release 包通过仓库外的 keystore 签名，相关配置读取以下环境变量（或 `~/.gradle/gradle.properties`）：`QDU_RELEASE_STORE_FILE`、`QDU_RELEASE_STORE_PASSWORD`、`QDU_RELEASE_KEY_ALIAS`、`QDU_RELEASE_KEY_PASSWORD`；未配置时 `assembleRelease` 只产出未签名包，无法安装。Gradle 依赖走腾讯云镜像，无需额外配置。

## 使用前须知

- **研究生系统的课表需要单独登录一次**。学校的课表系统（研究生系统）不在统一认证体系内，第一次进课表页时会引导你在它的登录页单独登录一次，之后会保持登录状态。
- **本科课表依赖选班**。公开课程总表里没有「你属于哪个班」的信息，第一次进课表页需要选择自己的行政班级；分级教学课（如大学英语）会列出多个平行教学班供任选，教室地点以学校实际安排为准。
- **校园网认证由系统完成**。连上 QDU-Web 后系统通常会自动弹出登录页面，App 只提供入口，不代你输入认证账号。
- **设备码的页面大多为微信设计**。这类页面有的只认微信内的访问方式，有的对普通浏览器返回错误，App 的做法是把识别结果交给你选的应用去打开，并提供「用微信或支付宝重新扫码」的入口；由微信自己完成打开与付款，比把页面硬塞进 App 内置浏览器更可靠。
- **部分功能仍以内嵌网页呈现**。办事大厅的具体服务、综合缴费等低频或涉及资金的页面直接打开学校网页，这些页面在手机上的显示效果取决于校方页面本身。

## 目前的困难与妥协

这个项目由个人在业余时间维护，能力与精力都有边界。下面这些是当下真实存在的困难，以及为此做出的取舍：

- **跟着学校系统的变化跑**。App 依赖的十几个校方网站与接口随时可能改版，改了对应的功能就会失效。开发者的做法是给每个接口留真实响应样本和单元测试，改版后能较快定位坏在哪一层；但单人业余维护，修复速度没有保证。
- **验证过的设备有限**。开发与验证主要在一台手机和几类模拟器形态上完成，市面上的屏幕尺寸、字体缩放、系统定制的组合无法穷举。如果你遇到文字被截断、按钮点不到或显示错乱，欢迎带着机型与系统版本反馈，这类问题多数能修。
- **校园网认证尝试过在 App 内代做，最终放弃了**。早期版本按公开资料推测认证协议、在应用内实现了认证表单，但从未真正跑通过，一直是「只能看不能用」。后来整套删掉，认证交还给系统弹出的登录页完成。这里保留这个失败记录，因为它体现了项目的做事方式：做不到就明说并撤掉，不用假界面撑门面。
- **有些数据只能随版本更新**。本科课表来自教务处公开的课程总表文件，App 不从网上拉取，教务处调整排课后要等新版本；电费接口只提供当前余额快照，所以画不了用量曲线、算不了「还能用几天」。来源里没有的数据，App 不会编。
- **通知提醒是本地的，不是服务器推送**。App 没有服务端，新通知只在你打开 App 时检查，命中你设置的关键词才发本地通知；App 完全关闭期间不会提醒。
- **一些功能排在了后面**。桌面小组件、课前提醒、课表导出等能力都已列入计划，但会等课表这类核心功能稳定之后再做；办事大厅背后几十个第三方系统也只做了「看清有什么服务」，逐个原生化不现实。

## 技术参考

- **语言与平台**：Kotlin，Jetpack Compose + Material 3，最低支持 Android 13（minSdk 33）。
- **主要依赖**：Room（本地数据库）、OkHttp（网络请求）、Jsoup（通知页面解析）、Hilt（依赖注入）、DataStore 与 EncryptedSharedPreferences（本机数据与加密凭据）、CameraX 与 ML Kit 条码识别（扫码，识别模型打进安装包、纯离线）。
- **数据来源**：全部来自学校公开或登录后的官方系统接口，逐个系统独立封装；接口解析配有基于真实响应样本的单元测试，校方改版时可以快速定位与修复。
- **参考项目**：开发过程中参考了同类高校开源项目的做法，如 ZZUPocket（结构与文档组织）、BJTUselfService（Compose 会话管理）等。
- **许可**：以 Apache License 2.0 开源，全文见仓库 `LICENSE` 文件。第三方依赖沿用各自上游许可。
